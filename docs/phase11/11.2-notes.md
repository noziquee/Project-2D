# Phase 11.2 – Arrow attack definitions and `projectile_speed`

Run in Godot 4.7.2 (headless). Before this step the 11.1 total was confirmed: `SUMMARY passes=623 failures=0`. With 11.2 to 11.4 together the run gives **`SUMMARY passes=669 failures=0`**. This step's share is **14 checks** (section WW: WW1 to WW13 plus WW11pre).

## Why
11.1 gave projectiles their own speed export. The speed of an arrow belongs to the attack, so it is data on `AttackDefinition2D`, and the arrow is a real scene with real art.

## What changed
- `AttackDefinition2D.gd`: new group **Projectile** with `projectile_speed` (px/s, 0 = the effect scene's own default). Melee effects ignore it. Every existing `.tres` is unchanged, so every melee attack has 0.
- `AttackEffect2D.gd`: new variable `projectile_speed` and a new **last** argument of `configure(...)`, `flight_speed: float = 0.0`. Old callers (tests, `fire_projectile`) still work.
- `ProjectileEffect2D.gd`: in `_ready()`, `speed = projectile_speed` when it is above 0.
- `AttackComponent2D.gd`: `_spawn_effect()` passes `active.projectile_speed`. This is the only change to the component: one more argument.
- `Arrow.tscn` (new, in `Characters/Components/Combat/`): same script and node layout as `ProjectileEffect2D.tscn`, with a `Sprite2D` (`2D_RPG_Assets/Weapon/Arrow.png`) in place of the placeholder polygon, a 16 x 8 hit area, `speed` 420 and `lifetime` 1.2. It is a standalone scene, not an inherited one: an inherited scene cannot drop the placeholder `Polygon2D`, and a hidden leftover node would be clutter.
- `ArrowAttackDefinition.tres` (`arrow_shot`): damage 4, knockback 120, hit stun 0.1, `pierce` off (stops at the first target), `projectile_speed` 420, `aim_weapon` on, `ai_attack_range` 180, hit effect as the sword's. Clips `bow_shoot` / `bow_return` (11.3).
- `ArrowHeavyAttackDefinition.tres` (`arrow_heavy`): damage 9, knockback 260, hit stun 0.25, `pierce` on with `max_targets` 3, `projectile_speed` 600, charge clip `bow_charge`. Clips `bow_heavy_shoot` / `bow_return`.
- `tests/smoke_checks.gd`: helpers `fire_arrow` and `hp_of`, section WW.

## Decisions
- **Hit-once and policy stay per effect (10.4).** The light arrow is spent by its first target. The heavy one goes through up to three.
- **Tunnelling.** Both speeds are under the rule from 11.1 (speed / 60 below the hitbox length): 7 px and 10 px per frame against a 16 px box. Check WW4 enforces it for the shipped arrows.
- **Wall impact.** Not built. An arrow that hits a wall just disappears (`world_hit` is emitted, nothing listens). `hit_contact` carries a target, so the impact effect would need `AttackComponent2D` to listen to `world_hit`; decide that when an arrow needs to puff on walls.
- **Validation messages** already name the attack and the clip (check WW12: `attack 'arrow_shot' on 'Player': weapon AnimationPlayer has no clip 'bow_shoot'`, reported when the arrow attack is tried on a sword).
