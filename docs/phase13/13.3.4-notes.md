The step is done only when your run prints 815.

## Why a modifier was needed
The 12.4 notes left stat modifiers out "until the buff skill has a use". A buff that does nothing is not a buff, so this step adds the smallest modifier that makes the guide's example work (Weapon Empowerment: more attack damage for a while) and nothing else.

## What changed
- `StatusEffectDefinition2D.gd`: new `damage_multiplier` (default 1 = none). The outgoing damage of the character that carries the status. Each stack adds `(damage_multiplier - 1)` once, so two stacks of 1.25 give 1.5. Bleed and any other status keep 1, so nothing existing changes. A buff status sets `tick_interval` 0 and `tick_damage` 0.
- `StatusController2D.gd`: `get_damage_multiplier()`, the sum of the running statuses' bonuses plus 1.
- `CombatResolver2D.gd`: step 0 of `resolve()`: `damage = round(damage x the attacker's multiplier)` (at least 1), then crit, then defense, as before. The multiplier is read from `hit.source`'s `status_controller` property by name, so melee, projectiles, areas, dashes and later skills and passives all get it with no change to the effects (the rule the resolver was built for). A source with no controller, a freed or null source, and periodic hits (status ticks) are unchanged.
- `SkillDefinition2D.gd`: `validate()` for BUFF: `status_effect` must exist and have a duration above 0. Either targeting works (the direction is ignored).
- `SkillComponent2D.gd`: `_execute_buff()` calls `apply_status(skill.status_effect)` on the caster's `StatusController2D`, so the status's own stack rule decides what a second use does. New refusal in `can_use()`: a BUFF skill is refused with a reason ("the character cannot carry statuses ...") when the caster has no controller, before anything is paid and before any cooldown starts. The order of the checks is now: unknown skill, dead, casting, attacking or charging, dashing, stunned, cooldown, what the behavior needs, cost.
- `Characters/Components/Status/EmpoweredStatusDefinition.tres` (new): `empowered`, 6 s, damage x1.5, no ticks, REFRESH.
- `Characters/Components/Skills/EmpowerSkillDefinition.tres` (new): Weapon Empowerment, slot 2, 15 mana, 10 s cooldown, SELF targeting, instant. **Not on any weapon** (13.5), and no shipped character has a `StatusController2D` yet, so the game plays as before.
- `tests/smoke_checks.gd`: EEE79 to EEE89, constant `EMPOWER_PATH`.

## Rules
- The status is applied when the skill **executes** (at once, or when the cast ends). A cancelled cast applies nothing and refunds, as in 13.2.
- The bonus is read **when a hit is resolved**, not when it is made. An arrow fired during the buff that lands after it ended gets no bonus, and one fired before it that lands during it does. This follows from doing it in the resolver; changing it later means stamping the multiplier onto the `HitData` when the effect spawns.
- The multiplier goes on the caster's **outgoing** damage only. It does not touch damage taken, tick damage, healing or knockback.
- Using the skill again while it runs does what the status's stack rule says (REFRESH for Empowerment: the time goes back to 6 s). IGNORE would refuse silently after the cost is paid, so a buff meant to be re-cast should use REFRESH or STACK.
- A buff skill on a character with no `StatusController2D` cannot be used. To try Empowerment, add a `StatusController2D` child to the player (name it exactly that).

## To use it in the editor
1. Give the character `ManaComponent2D`, `SkillComponent2D` **and `StatusController2D`** (see the 12.4 and 13.2 notes).
2. Add `EmpowerSkillDefinition.tres` to a weapon's **Skills > Active Skills** (slot 2). A new buff is one status `.tres` (set `damage_multiplier`, `duration`, `tick_interval` 0) and one skill `.tres` (`behavior` BUFF, `status_effect`).
