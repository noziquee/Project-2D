# Phase 13.3.2 - Area skill

Written October 25, 2026 **without running Godot** (the workspace has no Godot binary). 15 new checks (EEE51 to EEE65). Expected total: 776 + 15 = **`SUMMARY passes=791 failures=0`**. The step is done only when your run prints that number. Open the project in the editor once first (or run `godot --headless --path . --import`) so the new `class_name AreaEffect2D` is registered, then run the smoke test.

## What changed
- `Characters/Components/Combat/AreaEffect2D.gd` and `.tscn` (new): an `AttackEffect2D` subclass. A circle (the diameter is `hitbox_size.x`) centred `hitbox_offset` from where it spawns, in the effect's own frame, so (32, 0) is 32 px in front of the caster and (0, 0) is on the caster. It hits for `active_time` seconds (default 0.25), each target once, then frees itself; it frees itself at once when the hit policy (`max_targets`, `pierce`) is used up. It does not stop on walls. It draws a fading disc (`flash_color`), so a new area skill needs no art. Same `configure(...)` signature, same HitData / `apply_hit()` / team filter / crit / status path as a slash or arrow; no change to `AttackEffect2D`.
- `SkillComponent2D.gd`: `_execute()` handles AREA with `_execute_area()`. The area is configured from the skill's `AttackDefinition2D` like an attack; `area_radius` > 0 sets the diameter to `2 * area_radius`, 0 uses the attack's `hitbox_size`. With `targeting` SELF the offset is dropped and the area is centred on the caster (direction is then right, which only matters for knockback direction); with AIM_DIRECTION it sits `hitbox_offset` along the aim. The shared part (hit signals, host node, position) moved to `_place_effect()`, also used by the projectile; `_on_projectile_hit` / `_on_projectile_contact` are renamed `_on_effect_hit` / `_on_effect_contact` (nothing else referenced them). `skill_hit` now reports area hits too.
- `SkillDefinition2D.gd`: `validate()` checks AREA: an attack, an `effect_scene` that instantiates to an `AreaEffect2D` root, and no `max_range` (it does nothing for an area; place the area with `hitbox_offset`). Both targeting modes are allowed. A bad area skill is skipped by the component and refuses a weapon equip, with a message naming the skill.
- `Characters/Components/Skills/GroundSlamSkillDefinition.tres` (new): the shipped area skill. Ground Slam, slot 1, 15 mana, 6 s cooldown, instant, `area_radius` 40, centred 32 px in front. Damage 6, knockback 250, hit stun 0.2, `HitEffect.tscn` on impact. **Not on any weapon**: the game plays as before (EEE1 still holds). Attaching skills to weapons is 13.5.
- `tests/smoke_checks.gd`: EEE51 to EEE65, helpers `collect_area`, `GROUND_SLAM_PATH`, `AREA_SCENE_PATH`.

## Rules
- The area is made when the skill **executes** (at once, or when the cast ends). A cancelled cast spawns nothing and refunds, as in 13.2.
- Once spawned the area belongs to the world: cancelling, dying or switching weapon later does not remove it.
- Hit-once is per area. A target that walks into the circle during `active_time` is still hit; one that leaves is not un-hit.
- The caster and same-team characters are never hit (the shared filter). An area that can reach an enemy through a wall will hit it: there is no line-of-sight check.

## To use it in the editor
1. Give a character `ManaComponent2D` and `SkillComponent2D` (see 13.2 notes).
2. Open a weapon definition, **Skills > Active Skills**, add `GroundSlamSkillDefinition.tres` (slot 1). Nothing triggers it until input arrives in 13.4; to try it sooner, call `skill_component.try_use_slot(1)` from a script.
3. A new area skill is one `.tres`: `behavior` AREA, a slot, a cost, `area_radius`, and an `attack` whose `effect_scene` is `AreaEffect2D.tscn` (or a scene whose root extends `AreaEffect2D`) and whose `hitbox_offset` places the circle.
