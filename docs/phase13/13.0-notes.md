# Phase 13.0 - Decisions for active skills

Source: the roadmap's decisions table and `Phase_13_Active_Skills_Resource_Costs_Design_Guide.docx`. Nothing here is a code change; 13.1 and 13.2 implement it.

| Decision | Chosen | Why |
|---|---|---|
| Skill slots | **3 per weapon**, 0-based slots 0 to 2 (`WeaponDefinition2D.MAX_SKILL_SLOTS`) | Skills live on the weapon, so a weapon sets its own list; 3 is the guide's start value. |
| Cost resource | Optional per skill. `CostResource` is **NONE or MANA** | The player had no resource system, so one was added (`ManaComponent2D`). Stamina, energy, rage and charges are not built until a skill needs them. |
| Cooldown owner | `SkillComponent2D`, per skill id, counted in seconds | Never stored in the `.tres`. |
| Cast time | 0 (instant) by default; optional `cast_time` | |
| Channel | `channel_time` exists but must be 0; built last in 13.3 | |
| Commit point | **Cost paid and cooldown started when the cast starts** | One rule for every behavior. An instant skill executes at once. |
| Interruption | A damaging, non-periodic hit cancels the cast of an interruptible skill (`interruptible`, default true). Death and `cancel()` cancel any cast. A status tick never interrupts. | Matches `AttackComponent2D.interrupt()`, which also ignores periodic hits (12.4). |
| Refund | A cast cancelled before it executes **gives the whole cost back and clears that skill's cooldown** | A skill that never executed costs nothing. Same for every behavior. |
| Gating | Refused (nothing spent, no cooldown) while: dead, casting, attacking or charging, dashing, stunned, on cooldown, or the cost cannot be paid | Same gates as `AttackComponent2D`. |
| While casting | No attack, charge, dash, second skill or weapon switch can start (`context.is_casting`) | |
| Weapon switch | Skills change with the weapon; **cooldowns keep running** and are not reset | Switching weapons is not a free reset, as for attacks. |
| Skill data | A skill reuses `AttackDefinition2D` (`attack`) for projectile, area and dash skills and `StatusEffectDefinition2D` (`status_effect`) for buffs | No second copy of damage, crit, hit policy or status fields. |
