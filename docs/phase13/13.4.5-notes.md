# Phase 13.4.5 — One scene-based skill slot

**Status:** implemented in source; runtime verification pending the user's single smoke test after Phase 13.4 is complete. Do not report a passing `SUMMARY` until the user runs the full suite.

## Files

- `UI/HUD/SkillSlot.tscn` — reusable card scene with icon, radial `TextureProgressBar` cooldown overlay, seconds counter, hotkey and resource-cost labels, and an `AnimationPlayer`.
- `UI/HUD/SkillSlot.gd` — binds to `SkillComponent2D`; reacts to `cooldown_started`, `cooldown_finished`, `skill_refused` and `skill_started`; reads remaining cooldown and cast progress only for visual presentation.
- `UI/HUD/Styles/skill_slot_panel.tres` — editable panel style resource.
- `tests/smoke_checks.gd` — SSS1–SSS11 checks for scene structure, empty slots, bind behavior, counter formatting, cooldown, refusal feedback, ready feedback, affordability, no-cost skills and cast progress.
- `docs/phase13/13.4-plan.md` and `docs/Combat-Roadmap-Step-by-Step-Plan.md` — progress notes.

## Behavior

- Empty/unbound slot remains a valid frame with no icon/cooldown/cost badge.
- `bind(skill_component, skill, hotkey_text)` sets the slot's current skill and presentation.
- Cooldowns remain owned by `SkillComponent2D`. The slot uses `cooldown_started`, `cooldown_finished`, `skill_refused`, and `skill_started` for event feedback and reads `get_cooldown_remaining()`, `get_cooldown_duration()`, `get_casting_skill()`, `get_cast_progress()`, and `get_cast_remaining()` for its display.
- The radial wipe uses a scene-authored `TextureProgressBar` with a white `GradientTexture2D` texture and clockwise fill; no custom `_draw()` code or addon cooldown manager is introduced.
- A cast uses the same wipe with a separate blue tint. The cost badge hides when the skill has no resource cost. Insufficient mana dims the icon and cost badge.
- Animations are authored in the scene: `ready`, `denied`, `started`, and `unaffordable`.
