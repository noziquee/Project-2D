# Phase 13.3.1 - Projectile skill

Written and run October 25, 2026 in headless Godot 4.7.2 (Linux): 16 new checks (EEE35 to EEE50), **`SUMMARY passes=776 failures=0`** (760 + 16). The usual error lines in the log are the on-purpose rejections of earlier sections plus the ones named below; the leak lines at exit are not failures (see `docs/phaseV/V2-baseline-notes.md`). Still to do by hand: open `Main.tscn` in the editor (nothing shipped changed, but the new `.tres` has not been opened in the inspector).

## What changed
- `Characters/Components/Skills/SkillComponent2D.gd`: `_execute()` now runs the skill's behavior. For PROJECTILE it spawns the skill's `attack.effect_scene` (a `ProjectileEffect2D`) with the same `configure(...)` call `AttackComponent2D` uses, into the same host node (`Effects2D.get_host`), at `context.get_attack_origin()`, aimed along the skill's direction. The attack's `hit_effect_scene` spawns at every hit. New signal `skill_hit(skill, target, damage)`. `skill_executed` is emitted after the projectile is spawned. Other behaviors are unchanged (they still only emit `skill_executed`).
- `Characters/Components/Skills/SkillDefinition2D.gd`: `validate()` now checks a PROJECTILE skill: targeting must be AIM_DIRECTION, `attack` must exist, `attack.effect_scene` must exist, be instantiable and have a `ProjectileEffect2D` root. `SkillComponent2D.set_skills()` and `WeaponDefinition2D.validate()` already call `validate()`, so a bad projectile skill is skipped by the component and refuses a weapon equip, with a message naming the skill.
- `SkillDefinition2D.Behavior.NONE` (new, last in the enum so saved numbers do not change): does nothing when executed. See "Decision" below.
- `Characters/Components/Skills/PowerShotSkillDefinition.tres` (new): the shipped projectile skill. Power Shot, slot 0, 20 mana, 4 s cooldown, instant, `max_range` 300. Its attack is an inline `AttackDefinition2D`: `Arrow.tscn`, damage 8, knockback 200, hit stun 0.15, pierces up to 3 targets, speed 520 px/s (520 / 60 is below the 16 px hitbox, so no tunnelling), `HitEffect.tscn` on impact. It is **not** on any weapon: the game plays exactly as before (EEE1 still holds). Attaching skills to weapons is 13.5.
- `tests/smoke_checks.gd`: checks EEE35 to EEE50, helpers `collect_projectile` and `POWER_SHOT_PATH`, and `make_skill()` now makes NONE skills (see below).

## Rules
- The projectile is made when the skill **executes**: at once for an instant skill, when the cast ends for a skill with `cast_time`. A cast cancelled before that spawns nothing (the cost comes back, as in 13.2).
- Once spawned, the projectile belongs to the world, like a melee slash after its swing: cancelling, dying or switching weapon later does not remove it.
- `max_range` > 0 sets the projectile's `lifetime` to `max_range / speed`, using the attack's `projectile_speed`, or the scene's own speed when the attack sets none. 0 leaves the scene's lifetime. It is a distance limit in flight time, not a targeting range check: the skill can be used with no enemy in range.
- Direction: the one passed in, else the aim, else the facing, else right (unchanged from 13.2). SELF targeting is refused for projectile skills.
- Damage, crit, status effects, hit-once and the team filter are the ones of `AttackEffect2D` / `ProjectileEffect2D`. Nothing new in the damage path, so the resolver (defense, crit) applies as for an arrow.
- The skill does not play `weapon_animation` yet. The clip and its return to rest belong with the real skills in 13.5, when a weapon has a clip to play.

## Decision to confirm: `Behavior.NONE`
Once PROJECTILE needs an attack, the 26 checks of 13.2 (which build skills in code with the default behavior and no attack) would have failed validation. Instead of attaching an arrow to each of them, `make_skill()` now builds NONE skills, so those checks still test only cost, cooldown, cast and gating and fire nothing. NONE is also a handy placeholder. If you would rather not have it, the other way is to give `make_skill()` a real attack; say so and I will switch.

## To use it in the editor
1. Give a character the two nodes (see 13.2 notes: `ManaComponent2D` and `SkillComponent2D`).
2. Open a weapon definition, **Skills > Active Skills**, add `PowerShotSkillDefinition.tres`. Nothing triggers it until input arrives in 13.4; to try it sooner, call `skill_component.try_use_slot(0)` from a script.
3. A new projectile skill is one `.tres`: `behavior` PROJECTILE, a slot, a cost, and an `attack` whose `effect_scene` is a `ProjectileEffect2D` scene.
