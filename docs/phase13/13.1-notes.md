# Phase 13.1 - `SkillDefinition2D` and `active_skills`

Written and run in Godot 4.7.2 (headless, Linux). Checks EEE1 to EEE8 (8 new). Together with 13.2 the run is **`SUMMARY passes=760 failures=0`** (726 + 34).

## What changed
- `Characters/Components/Skills/SkillDefinition2D.gd` (new resource): `id`, `display_name`, `icon`, `slot`, `behavior` (PROJECTILE, AREA, DASH, BUFF), cost (`cost_resource` NONE or MANA, `cost_amount`), timing (`cooldown`, `cast_time`, `channel_time` reserved at 0, `interruptible`), targeting (`targeting`, `max_range`, `area_radius`), `weapon_animation` (optional clip), `attack` and `status_effect`. `validate(animation_player, slot_count)` returns messages naming the skill.
- `WeaponDefinition2D.gd`: `active_skills: Array[SkillDefinition2D]` (group Skills), `MAX_SKILL_SLOTS = 3`, `get_skill(id)`, `get_skill_in_slot(slot)`, `get_skill_ids()`. `validate()` reports too many skills, empty entries, each skill's own problems, duplicate ids and duplicate slots; the clip check (weapon player or the weapon's own scene) now includes each skill's `weapon_animation`. No shipped weapon has skills, so nothing changes in the game.
