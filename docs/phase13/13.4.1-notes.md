## What changed
Only `Characters/Components/Skills/SkillComponent2D.gd` (and the tests).

New signals:
- `cooldown_started(skill, duration)`: a cooldown began. Emitted once per use, before `skill_started`. **Not emitted for a skill whose cooldown is 0** (see below).
- `cooldown_finished(skill_id)`: a cooldown ended, either because it ran out or because a cancelled cast cleared it. **It carries the id, not the skill** (the plan said the skill): a cooldown keeps running after a weapon switch, and by then the skill may no longer be set. The cooldown is already gone when the signal arrives, so `get_cooldown_remaining()` is 0 inside a listener.
- `skill_refused(skill, reason)`: a known skill was refused by `can_use()`; `reason` is the same text `can_use()` returns. Not emitted for an unknown id or an empty slot (there is no skill to shake).
- `skills_changed`: `set_skills()` ran, which is what equipping a weapon calls. Emitted once per call, even when the result is the same list.

New functions:
- `get_cooldown_duration(skill_id)`: the full length of the cooldown running now, 0 when none. With `get_cooldown_remaining()` it gives the wipe its fraction. Works for a skill that is no longer set.
- `get_cast_progress()`: 0 to 1 of the running cast, 0 when not casting.

## Behavior notes
- **A skill with cooldown 0 no longer leaves an entry in the cooldown dictionary.** Before, it stored 0.0 and the next physics frame erased it. Nothing could see the difference (`get_cooldown_remaining()`, `is_ready()` and `can_use()` give the same answers), and it keeps `cooldown_finished` from firing for a cooldown that never was.
- When cooldowns run out in the same frame, the dictionary is finished first and the signals are sent after, so a listener that uses a skill again cannot disturb the loop.
- When a cast is cancelled, the order is: cost refunded, `cooldown_finished`, then `skill_cancelled`. A HUD may show a "ready" flash for the first; whether it should for a cancel is decided in 13.4.5.
- Everything else (gating order, refunds, cooldowns across weapon switches) is as in 13.0 and 13.2.

|---|---|

| FFF7 | An unknown id or an empty slot emits no `skill_refused`. |
