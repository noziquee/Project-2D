# Phase 10.3 – exported node paths on `AttackSlash2D`

Not run (no Godot in the editing environment). Open the project, read the Output panel, run the smoke test and paste the SUMMARY line and any `CHECK FAIL` lines. This step adds **6 checks** (section SS: SS1a to SS3) and changes none, so expect your previous total + 6. No new class this time, so no import step is needed (but `AttackEffect2D` from 10.2 still needs `godot --headless --import --path .` once).

Expected in the Output log (not failures): one `AttackSlash2D: hitbox_path 'Nowhere' does not lead to an Area2D` error (SS3).

## Why
Finding B of the guide: `AttackSlash2D.gd` looked up four nodes by fixed `$` paths, so an effect scene built differently could not be used without editing the script. The clip name was already per attack (`effect_animation`, 9.8a).

## What changed
- `AttackSlash2D.gd`: four exported `NodePath`s under the group **Scene nodes (10.3)**: `animation_player_path`, `hitbox_path`, `collision_shape_path`, `hitbox_origin_path`. Their defaults are today's names, so `AttackSlash2D.tscn` and every inherited scene are unchanged (a default is not saved in a scene).
- The `@onready` lookups became one `_resolve_nodes()` in `_ready()`. A path that leads nowhere, or to the wrong kind of node, is reported by property name (`hitbox_path '...' does not lead to an Area2D`) and the effect removes itself, instead of failing later with a null error. `_can_hit()` and the hit origin are safe when a node is missing.
- `scene_lacks_animation()` (used by `validate_definition()` and `validate_equip()`) now reads the scene's own `animation_player_path`, so an effect scene with its player somewhere else is validated against that player. The constant `ANIMATION_PLAYER_PATH` stays as the default.
- `tests/smoke_checks.gd`: section SS. SS1 the shipped scene keeps the defaults and they resolve; SS2 a scene with an `AltPlayer` and `animation_player_path` set plays and frees itself, and the clip check uses that player; SS3 a broken path logs an error and removes the effect.
- `IMPLEMENTATION_NOTES.md`, `README.md`, the roadmap: wording.

## How to use it
In an inherited effect scene, select the root and open **Scene nodes** in the Inspector. Point each path at your own node. The clip still comes from the attack's `effect_animation`.

## Not changed
The `AttackSlash2D.tscn` node names, every `.tres`, and the sweep itself. The effect still spawns at the attacker's origin (10.5) and hit policy is still per effect (10.4).

Nothing should look different.
