# Phase 10.1 – remove the legacy slash fallbacks

Not run (no Godot in the editing environment). Open the project once, read the Output panel, run the smoke test and paste the SUMMARY line and any `CHECK FAIL` lines. This step adds **7 checks** (section QQ: QQ1a to QQ6) and **rewrites one** (I27, same number, same count), so expect your previous total + 7. The previous total is still unconfirmed from 9.2 on: run Phase V first if you have not (see `docs/Combat-Roadmap-Step-by-Step-Plan.md`).

Expected in the Output log (not failures): `AttackComponent2D rejected definition` errors naming `qq_no_fx` and `test_no_effect`, a `WeaponController2D` message naming `effect_scene`, and `AttackComponent2D needs a character context, an attack_definition, and a weapon AnimationPlayer` from the bare component in QQ6.

## Decision made
A character with no `attack_definition` cannot attack and logs an error (no hidden default).

## Why `player.tscn` changed
The player never set `attack_definition` in its scene. It got `DefaultAttackDefinition.tres` from the script's default value, then the sword's `WeaponController2D` replaced it at start-up. With the default gone, `AttackComponent2D.initialize()` would have failed for the player. `player.tscn` now sets `attack_definition = DefaultAttackDefinition.tres` (the same resource as before, so nothing changes in play). The goblin already set its own.

## What changed
- `AttackComponent2D.gd`: removed `DEFAULT_ATTACK`, `DEFAULT_SLASH`, the `attack_slash_scene` export, the runtime `slash_scene` and `set_slash_scene()`. `attack_definition` has no default. `initialize()` logs `needs a character context, an attack_definition, and a weapon AnimationPlayer` when any is missing. `_spawn_effect()` uses only the attack's `effect_scene`.
- `validate_definition()` now rejects an attack with no `effect_scene`, naming it. That covers `set_attack_definition()`, `attacks`, `equip()` and `validate_equip()`. The check runs **last**, so every existing message (missing clip, bad charge, bad effect scene) still comes first and tests KK4a to KK4f are unaffected.
- `Character2D.gd`: the `attack_definition` shim passes the value straight through. Assigning null is refused and the previous attack stays.
- `AttackDefinition2D.gd`: the `effect_scene` tooltip says it is required.
- `player.tscn`: explicit `attack_definition` (see above).
- `tests/smoke_checks.gd`: I27 rewritten on purpose (a definition with no `effect_scene` is refused and the previous attack stays; before, it checked the legacy fallback). New section QQ. `M6` is unchanged.
- `IMPLEMENTATION_NOTES.md`, `README.md` and the roadmap: wording updated.

## What to check in play
Nothing should look different. If the player cannot attack, read the Output panel: an `AttackComponent2D needs ...` error means `player.tscn` did not load its `attack_definition` (open `AttackComponent2D` in the Scene dock and assign `DefaultAttackDefinition.tres`).

## For new characters
Set `AttackComponent2D.attack_definition` in the scene and make sure every attack has an `effect_scene`.

## Not changed
`DefaultAttackDefinition.tres` stays: the player scene, the sword's weapon definition and many tests use it.
