## Why
Guide finding on effect origin: `_spawn_effect` always used `character.global_position`, so an attack could not start at a hand, a staff tip or a bow.

## What changed
- `Character2D.gd`: new export `attack_spawn_point: Marker2D`. If it is empty, a child named `AttackSpawnPoint` is used. A node with that name that is not a `Marker2D` is ignored with a warning. The value is passed to the context.
- `CharacterContext2D.gd`: `attack_spawn_point` and `get_attack_origin()`. It returns the marker's global position when the marker is alive and in the tree, otherwise the character's position (so a freed marker is safe).
- `AttackComponent2D.gd`: `_spawn_effect` sets `global_position = context.get_attack_origin()`.
- `tests/smoke_checks.gd`: three helpers (`fresh_far_prepared`, `live_slashes`, `mount_exported_marker`) and section UU.
- `docs/Combat-Roadmap-Step-by-Step-Plan.md`, `IMPLEMENTATION_NOTES.md`, `README.md`: wording.

## Decision made
No marker was added to `player.tscn` or `BasicEnemy2D.tscn`. The marker is optional, and an unneeded marker at (0, 0) would only be another text-edited scene to check. Add one in the editor when a character needs it.

## How to use it
Add a `Marker2D` named `AttackSpawnPoint` as a child of the character and move it. A marker directly under the character does not rotate with the aim. Put it under `WeaponFacingPivot` if it should follow the aim.

## Not changed
The hitbox offset still comes from the attack definition and is applied relative to the effect, so it now starts from the marker. Facing flips of the goblin sprite do not mirror a marker placed under the character; a marker under `AnimatedSprite2D` mirrors with it.
