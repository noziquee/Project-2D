# Phase 10.4 – hit policy: `max_targets` and `pierce`

Not run (no Godot in the editing environment). Open the project, read the Output panel, run the smoke test and paste the SUMMARY line and any `CHECK FAIL` lines. This step adds **7 checks** (section TT: TT1, TT2a to TT2e, TT3) and changes none, so expect your previous total + 7. There is no new class, so no import step beyond the one 10.2 needs. No expected errors in the log.

## Decision made
Hit-once stays **per effect**: one effect hits each target once, and three effects spawned by one swing (a flurry) can each hit the same target. That is what the slash always did. Arrows will be per projectile, which is the same rule.

## Why
Finding B of the guide: an effect could not say how many targets it may hit, and a projectile needs to stop at its first one.

## What changed
- `AttackDefinition2D.gd` (group **Hit**): `max_targets` (0 = no limit, range 0 to 20) and `pierce` (default on). The defaults are exactly today's melee behavior, so no `.tres` changes.
- `AttackEffect2D.gd`: `configure(...)` takes two new last arguments, `max_target_count` and `pierces`, with defaults, so every existing caller still works. After each hit the effect checks its policy: the cap is `max_targets`, or 1 when `pierce` is off. When the number of targets it has touched reaches the cap, it is **spent**: `is_spent()` returns true, no further target is hit, and the `_on_spent()` hook is called. The slash leaves that hook empty (its animation plays out, but it cannot hit anything more); the projectile in Phase 11 will free itself there.
- A target that is touched but takes no damage (for example while invulnerable) still counts toward the cap, so an arrow is stopped by it.
- `AttackComponent2D.gd`: passes the attack's `max_targets` and `pierce` when it spawns the effect.
- `tests/smoke_checks.gd`: section TT. TT1 defaults of new and shipped attacks; TT2a to TT2e three goblins hit in order by a bare effect (no limit, limit 1, pierce off, limit 2, limit 3); TT3 the spawned effect carries the attack's policy.
- `IMPLEMENTATION_NOTES.md` and the roadmap: wording.

## How to use it
On an attack's `.tres`, open **Hit**. `max_targets = 1` makes a single-target strike; `pierce` off does the same and also marks the effect spent (what a projectile wants).

## Not changed
No shipped attack uses either field yet, so nothing looks different in play. Melee order is whatever order the physics engine reports overlapping bodies; use `max_targets` only where "any one of them" is fine.
