# Phase 10.2 – `AttackEffect2D` base class

Not run (no Godot in the editing environment). **Run `godot --headless --import --path .` first**: this step adds a new `class_name` (`AttackEffect2D`) that `AttackSlash2D` extends, and Godot has to register it (it also writes `AttackEffect2D.gd.uid`). Then open the project, read the Output panel, run the smoke test and paste the SUMMARY line and any `CHECK FAIL` lines. This step adds **11 checks** (section RR: RR1 to RR5), so expect your previous total + 11. No existing check changed.

Expected in the Output log (not failures): one `AttackComponent2D: effect scene for attack 'rr_plain' must have an AttackEffect2D script` error (RR5).

## Why
Finding B of the guide: the effect contract was one class, `AttackSlash2D`, and `AttackComponent2D` required exactly that class. A projectile or an area effect would have meant editing the component. Now the component only needs an `AttackEffect2D`.

## What changed
- New `Characters/Components/Combat/AttackEffect2D.gd` (a `Node2D`): the fields `configure(...)` sets (same arguments, same clamping as before), the `hit_contact` and `hit_confirmed` signals, `DEFAULT_ANIMATION`, and the shared hit rules in `_try_hit(target)` (valid target, not the attacker, `damageable` group, `apply_hit` or `take_damage`, not the same team, once per effect, `HitData` into `apply_hit`). Two small hooks for subclasses: `_can_hit()` (when the effect may hit) and `_get_hit_origin()` (where the hit area is, for the impact point).
- `AttackSlash2D.gd` now `extends AttackEffect2D` and keeps only the slash parts: the node lookups, the scene's animation player path, `scene_lacks_animation()`, the hit window (`_can_hit` is the animated `CollisionShape2D:disabled` track) and the hitbox sweep. Behavior is meant to be identical.
- `AttackComponent2D.gd`: tracks and spawns `AttackEffect2D` (was `AttackSlash2D`). The error for a wrong effect scene now says it needs an `AttackEffect2D` script.
- `AttackDefinition2D.gd`: the `effect_scene` tooltip says the root needs a script that extends `AttackEffect2D`.
- `tests/smoke_checks.gd`: section RR. RR1 the slash is an effect; RR2 `configure()` on the base; RR3 team, hit-once and self-hit rules on a bare base-class effect; RR4 the component spawns, tracks and cancels a non-slash effect; RR5 a scene with a plain `Node2D` root is refused with an error.
- `IMPLEMENTATION_NOTES.md`, `README.md`, the roadmap: wording.

## Not changed
`AttackSlash2D.tscn`, every `.tres`, and the fixed node paths inside `AttackSlash2D.gd` (that is 10.3). `AttackSlash2D.scene_lacks_animation()` is still the clip check, so a non-slash scene is not judged for its clip (it returns false when the scene has no standard animation player).

## What to check in play
Nothing should look different: light, light2 and heavy slashes, hits, friendly-fire, impact effects.
