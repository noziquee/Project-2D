# H7.6: touch controls (October 28, 2026)

Status: written, not yet run (checks H7-40 to H7-67, part `h7_touch`; with everything from H7.2 on expect `SUMMARY passes=1265 failures=0`). Needs a try on a phone, or on a desktop with the debug switch below.

## What it is

| File | Role |
|---|---|
| `UI/Touch/VirtualStick.gd` | An on-screen stick. Presses four named actions with the push as their strength (`Input.action_press(action, strength)`), so `Input.get_vector` reads it like a controller stick. One finger owns it from touch-down to lift. |
| `UI/Touch/TouchActionButton.gd` | A round button for one action. Holds the action while a finger is on it, so a tap is a press and a hold is a hold (`attack_light` and `attack_heavy` charge while held). |
| `UI/Touch/MobileControls.gd` | Builds the layout in `_ready`, shows it only on touch, and hides it (releasing everything held) on keyboard/mouse or controller. |

`MobileControls` is a node under `HUD` in `Main.tscn`. It finds `InputModeManager` by its group (after the first frame: the manager sits later in the scene than the HUD) and follows `device_changed`.

## Layout (base viewport 1280 x 720, anchored to the bottom corners, 30 px from the edges)

- Bottom left: the move stick (`move_*`), 180 px.
- Bottom right: a 3 x 3 grid of 80 px buttons, then the aim stick (`aim_*`, D11), 180 px. The grid, row by row: `skill_1 skill_2 skill_3` / `weapon_next attack_heavy dash` / (empty) (empty) `attack_light`. `attack_light` is the one next to the aim stick. Change the order in `MobileControls.GRID`.
- The right cluster starts at x = 794 at the base width, clear of the skill bar (it ends at x = 770). The `expand` stretch keeps 1280 as the minimum width, so this holds at every landscape ratio; only the height grows.
- Sizes and margin are exports on `MobileControls`: `stick_size`, `button_size`, `button_gap`, `edge_margin`.

## Why `emulate_mouse_from_touch` is off

`project.godot` now has `input_devices/pointing/emulate_mouse_from_touch=false`. With Godot's default, every touch also arrives as a left mouse click, and `attack_light` is bound to the left mouse button: touching the move stick would swing the weapon. The cost: the hotbar slots no longer react to a finger. On touch the skill buttons of this overlay take their place; the hotbar stays as a display.

## Rules

- No combat code here. The player reads the same actions a key or a controller sets.
- A stick or button lets go only of the actions it pressed itself, never of a key held on another device.
- A hidden overlay ignores touches and holds nothing.
- A finger belongs to the control it landed on until it lifts; a second finger on a held stick is ignored, so two thumbs work together.
- The aim stick uses the H7.4 rule in `player.gd`: pushing it sets the aim, letting go keeps the last aim.

## To try

1. On a desktop, select the `MobileControls` node (`Main.tscn` > `HUD` > `MobileControls`) and tick `Debug Force Visible` in the Inspector. To use the mouse as a finger, also turn on Project Settings > Input Devices > Pointing > Emulate Touch From Mouse (switch both back afterwards: with that setting on the mouse stops acting as a mouse).
2. Drag the left stick: the player walks. Drag the right stick and tap `Atk` with the bow equipped: the arrow goes where the stick points. Hold `Atk`: it charges. Tap `1` to `3` and `Swap`.
3. On a phone export, check the overlay shows at start, that nothing swings when you only touch a stick, and that every button is reachable with a thumb.

## Open for the play-test

Aiming with the right thumb leaves one thumb for the attack buttons, so shooting while aiming means sliding the thumb. If it feels wrong, the next options are the aim stick firing `attack_light` when pushed (twin-stick) or an auto-aim assist. Both are a design choice, not a bug.
