## What it is

`Platform/InputModeManager.gd` is a node (`InputModeManager` in `Main.tscn`, group `input_mode_manager`). It only watches input and reports which kind of device was used last. It changes nothing in combat, aiming or the input map.

- `active_device`: `Device.KEYBOARD_MOUSE`, `Device.CONTROLLER` or `Device.TOUCH`.
- `device_changed(device)`: emitted when the active device changes, never twice in a row for the same device.
- `is_touch()`, `is_controller()`, `has_controller()` (a controller is plugged in; says nothing about which device is in use), `set_device(device)` (a debug switch or a future settings screen).
- `default_device_for(features)`: the start mode from OS feature names.

## Rules

| Rule | Why |
|---|---|
| Starts as TOUCH on Android, iOS and web on those; KEYBOARD_MOUSE elsewhere | The guide: show touch controls by default on mobile only |
| A connected controller does not become active until it is used | The guide: do not assume a connected controller is the active device |
| A key press, a real mouse click or mouse movement means KEYBOARD_MOUSE | Last device used wins |
| A controller button press, or a stick pushed past 0.4, means CONTROLLER | A resting stick drifts a little; that must not switch the device |
| A touch or drag means TOUCH | |
| Key and button releases, key repeat, and mouse events made from touches (device id emulation) are ignored | Otherwise every tap would flip touch to mouse |
| Unplugging the last controller while it is active falls back to the start mode | |
