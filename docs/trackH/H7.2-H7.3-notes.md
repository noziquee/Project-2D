## H7.2 Display (`project.godot`)

| Setting | Before | Now |
|---|---|---|
| `display/window/size/viewport_width` x `viewport_height` | default (1152 x 648) | 1280 x 720 |
| `display/window/stretch/mode` | `viewport` | `canvas_items` |
| `display/window/stretch/aspect` | (default `keep`) | `expand` |
| `display/window/handheld/orientation` | default | 0 (landscape) |

The camera zoom stays 3. The visible world is the viewport divided by the zoom, so at 16:9 it is about 427 x 240 px (it was 384 x 216).

**Look at the pixels** (decision D9): with `canvas_items`, scaling is not locked to whole numbers, so at some window sizes pixels can look uneven or shimmer while moving. The default texture filter is already nearest. If it bothers you, put `window/stretch/mode` back to `viewport` (and `aspect` to `keep`), which restores the old fixed look and drops the extra world on wide windows. The setting names are the Godot 4 ones; check them in Project Settings > Display > Window.

## H7.3 Camera and world

`World/CameraBounds2D.gd`, added to `Main.tscn` as the node `CameraBounds` (`floor_path = ../ArenaFloor`), sets the player camera's four limits to the bounds of the arena floor polygon (-500, -320, 500, 320, so 1000 x 640) when the level loads. Edit the floor and the limits follow. It does not touch the zoom.

World shown with `expand` at zoom 3 (base 1280 x 720):

| Window shape | World on screen | Fits the 1000 x 640 floor |
|---|---|---|
| 16:9 | 427 x 240 | yes |
| 21:9 | 560 x 240 | yes |
| 32:9 | 853 x 240 | yes |
| 16:10 | 427 x 267 | yes |
| 4:3 | 427 x 320 | yes |
| 5:4 | 427 x 341 | yes |
| 1:1 | 427 x 427 | yes |
| 9:16 portrait | 427 x 758 | **no** (D10: landscape only) |

Anything wider than about 2:3 portrait fits. A very tall desktop window would show past the floor edge; that is the known limit behind D10.
