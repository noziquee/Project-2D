# H8.5b: assist fix, range circle, target marker (October 28, 2026)

Status: written, **not run** (no Godot here). Run `--only=h8_aim,h8_aim_state`, then the full suite. Changed checks: H8-79, H8-82 (and a restore after H8-84). New checks: H8-232 to H8-238.

## Why a tap went in a "random" direction
1. The sword's `assist_range` was 48 px (+ 8 px body margin), so an enemy 60 px away was "near" to you but invisible to the assist.
2. The search fan was 120 degrees around the aim. On touch with no drag the aim is only the last aim or the facing, so an enemy beside or behind you was outside it.
3. With no target the tap goes to the last aim, which can be stale (the direction of an enemy you killed earlier). That fallback is the PDF's rule and is unchanged.

## What changed
- Sword slashes: `assist_range` 48 -> 96 (Inspector: `Sword_Slash1/2.tres`, group "Aim assist"). Bow unchanged (240).
- `Player.light_assist_angle` default 120 -> 360: a tap looks all round. Set it to 120 for a front-only search again.
- Nearer enemies win more often: the light fan now uses `angle_weight` 0.4 (const `LIGHT_ASSIST_ANGLE_WEIGHT` in `player.gd`; the PDF default 0.7 stays for every other shape). `FanAimShape2D.angle_weight` / `make(angle, reach, weight)` are new and default to the old value.
- **Blue circle** on the ground round the player = the light attack's `assist_range` (how far a tap looks for a target; it is not the swing's hitbox). `Player.show_attack_range`.
- **Red ring** under the enemy the next tap will pick, from the same `pick_target` call the attack makes. `Player.show_target_marker`.
- Both are hidden while a heavy attack or a skill shows its own aim shape, when the player is dead, and when `aim_indicators` is off. Drawing only; combat is unchanged.
