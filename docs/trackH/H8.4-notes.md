# H8.4: persistent aim state and the activation hook (October 28, 2026)

Status: written, **not yet run** (no Godot here). 16 new checks, H8-63 to H8-78, in a new part `h8_aim_state` (it needs a fresh Main scene). Keyboard/mouse and controller aiming behave as before; only a touch player with no aim yet changes (below).

## Changed files
| File | Change |
|---|---|
| `Characters/Core/CharacterContext2D.gd` | New `last_aim_direction` (zero until there is one). The last non-zero facing is the existing `facing_direction` (never zero), so no second field. |
| `player.gd` | Remembers live aim; `set_manual_aim / clear_manual_aim / get_manual_aim`; `get_targeting_service()` (a child `TargetingService2D`, made on first use, so no scene edit); `_direction_for_activation(shape)`; `_get_attack_direction()` override; `_physics_process` override that closes the activation window each frame; skill slots use the activation path. |
| `tests/h8_aim_checks.gd`, `tests/smoke_checks.gd` | The checks and the `h8_aim_state` part. |

## How it works
- `_get_aim_direction()` stays the cheap per-frame read (facing, weapon pivot, charge follow). It now also stores the stick aim and, off touch, a non-zero mouse aim as `last_aim_direction`. A manual aim, when set, is the live aim, so the weapon follows a drag.
- Character2D calls `_get_attack_direction()` every frame (even as the argument of an empty attack request), so assistance cannot live there. The player opens an **activation window** at the start of `_sample_attack_input` and closes it at the start of the next physics frame. Only inside it, and only with a light attack, charge begin or charge release pending, is `_direction_for_activation()` used. Everything else is the plain aim.
- `_direction_for_activation(shape)` calls the service: `begin_action()`, then `resolve(origin, intended, shape, last_aim, facing, manual)`. `manual` is true while a manual aim is set or the right stick is pushed. The result is remembered as the last aim when it came from a manual aim, a target or the intended aim (not from a fallback).
- All three call sites pass `null` as the shape: **no assistance yet**. H8.5 (light arc), H8.6/H8.7 (heavy and skill shapes) supply the shapes.

## One behavior change (touch only)
On touch, a pointer that never moved is no aim. Before, a touch player who never used the aim stick got the stale mouse position as the aim. Now a tap goes along the last valid aim, else the facing, else right. Once the stick has been used, its last aim still applies as before.

## Decisions made here
1. The right stick counts as manual aim while pushed; the mouse does not (it is the intended aim, so assistance may refine it later).
2. Whoever sets a manual aim clears it when the drag ends (H8.8 does this for the touch buttons), so the next action returns to assistance. For a heavy attack, the button must set the final aim before the release frame and clear it after.
3. The service is created in code. If you prefer it authored, add a `TargetingService2D` child named `TargetingService2D` to `player.tscn`; the player will use it.
