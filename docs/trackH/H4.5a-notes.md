# H4.5a: the suite is a list of runnable parts

Written Oct 27, 2026. Not run: no Godot in the sandbox. Expected after this step: `SUMMARY passes=1190 failures=0` (1188 + H4-26 and H4-27).

## Why

`tests/smoke_checks.gd` is one 8,000-line script. Checking one change meant running all of it. The root cause: `_run()` was a single 5,300-line function (sections A to P8) with 22 `await run_*_checks()` calls pasted at its end, so nothing could be selected, and nothing noticed if a new group was never added to that list.

## What changed

- `_run()` was renamed `run_core_checks()` (body untouched, minus the 22 trailing calls). H4.5c then split that function into ten parts, see `H4.5c-notes.md`.
- New `const PARTS` (name -> method), in the order a full run uses. New `_run()` walks it and prints `PART <name> passes=N failures=M` after each part.
- `--only=a,b` runs just those parts. `--list` prints the names. An unknown name stops with exit code 2 (a typo never runs nothing quietly). `--record-errors` together with `--only` is refused (a partial run must not overwrite `tests/expected_errors.txt`).
- A partial run prints `PARTIAL RUN: ...` before the SUMMARY line. `tools/run_checks.sh` shows the `PART` lines and does not say "copy into STATUS.md" for a partial run.
- H4-26: every registry entry names a method that exists. H4-27: every `run_*_checks` method is in the registry (so a forgotten group fails the run).

## Order dependencies checked by reading

The only shared mutable state I found is the clip-return mode (`set_clip_returns`): set to true at start, flipped to false at the start of P10 and back to true at its end. So every part starts in the same mode. Not proven by a run: parts that edit other shared resources would only show up when a part is run alone and fails while the full run passes.
