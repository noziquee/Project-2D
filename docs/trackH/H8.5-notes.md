## How it works
A light tap is an activation (H8.4). The player builds a `FanAimShape2D` of `light_assist_angle` degrees and `assist_range` pixels and hands it to the targeting service, which picks the best eligible target and returns the direction to it. Axis of the fan: the aim the player gives, else the last aim, else the facing. No target: the aim is unchanged. A pushed stick or a drag (manual aim) skips the search. The attack component and the swing's hitbox are untouched; only the direction it receives changes.

## Decisions made here (tell me if you disagree)
1. **Reach is per attack, the angle is project-wide.** You chose one project-wide arc; the reach has to differ (a sword and a bow), so it lives on the attack as data.
2. **48 px for the sword, 240 px for the bow** are starting values. The bow's arrow flies about 500 px, so 240 keeps "nearby". Tune in the Inspector: Sword_Slash1/2 and Bow_ArrowShot, group "Aim assist".
3. **Assist applies on every device**, not only touch. With the mouse, a tap swings toward an enemy within 60 degrees of the cursor and inside the reach. Set `light_assist_angle` to 0 on the player to switch it off.
4. The enemy arrow, goblin attacks and heavy attacks have `assist_range` 0 (no assist).

## Not covered yet
