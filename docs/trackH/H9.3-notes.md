## The design change (T1, D20)
- **Before (H8.5):** a light tap searched a fan of `attack_range` radius, so only enemies inside the weapon's reach were
  targets, and the red ring showed only on those.
- **Now:** a light tap searches **what the camera shows** (`ViewAimShape2D`). Range decides nothing about who can be
  targeted. An enemy 400 px away on screen is selected, the tap turns toward it and the marker is on it. The swing still
  only reaches `attack_range`: closing the gap is auto-approach (H9.4), which is not built yet, so until then a tap at
  a far target swings toward it and misses.
- **Unchanged:** heavy attacks and skills keep their own `aim_shape` and the H8 rule that a target must be inside it
  (T3 clips those shapes to their own circle in H9.5). The blue circle is still the light attack's real
  `attack_range`; it is now drawn from the attack, not from the search shape.
- **Markers (D20):** the selected target has the strong ring, every other eligible target in view a light ring.
  `Player.show_other_targets` (default on) turns the light rings off; `show_target_marker` still hides all markers and
  `show_attack_range` still hides the circle.

## What changed
- New `Characters/Components/Aim/ViewAimShape2D.gd`: an `AimShape2D` holding the visible rectangle (plus the fan angle
  and weight). Inside the rectangle (grown by the target margin) is eligible; the aim still scores candidates, the
  nearer one wins ties as before.
- `AimShape2D.keeps_target()` (new): whether an action's kept target may stay. Default is the old "within max_range +
  margin"; the view shape keeps a target while it is on screen. `TargetingService2D._still_good` calls it, so heavy
  attacks and skills behave exactly as before.
- `TargetingService2D`: `get_view_rect()` (the viewport's canvas transform inverted over the visible rectangle, so zoom and
  camera limits are respected), `make_view_shape(angle, weight)`, `is_in_view(node)`, and `set_view_override(rect)` /
  `clear_view_override()` for tests and cut scenes.
- `AssistIndicator2D`: `show_state(range, target, others = [])`, `get_other_targets()`, and the colours and radius of the
  light ring (`other_marker_fill`, `other_marker_edge`, `other_marker_radius`), visible in the editor preview.
- `player.gd`: `_light_shape_for()` returns the view shape (null only when `light_assist_angle` is 0 or the attack is
  unknown); an attack with `attack_range` 0 is now assisted too; `_update_assist_indicator()` draws the circle from the
  attack's `attack_range` and the markers from the view.

## Checks edited (they described the old range rule)
H8-83 (a visible target beyond `attack_range` is now picked), H8-85 (`attack_range` 0 is assisted), H8-235 (a target beyond
the reach but in view keeps its marker). H8-86 now resets the last aim first because H8-85 remembers an assisted aim.
