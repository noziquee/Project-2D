# Phase 12.1 – Route all damage through one function

Written and run in Godot 4.7.2 (headless, Linux) on the Oct 24 archive: **9 new checks, all passing** (section AAA, AAA1 to AAA9). Expected total after this step: previous total + 9 (680 + 9 = **689**). See "Run result" for what the archive gave in the run done here.

## Why
Defense (12.2), crits (12.3) and statuses (12.4) all change the damage of a hit. They need one place to live, so melee, projectiles, skills and passives never need their own copy of the formula.

## What changed
- `Characters/Components/Combat/CombatResolver2D.gd` (new): `class_name CombatResolver2D`, a `RefCounted` with one static function, `resolve(hit: HitData, health) -> HitData` (see Decisions for the second argument). It returns the hit unchanged. A static counter, `resolve_calls`, lets the smoke test prove a damage source reached it; nothing in the game reads it.
- `Characters/Components/Health/HealthComponent2D.gd`: `apply_hit()` calls `CombatResolver2D.resolve(hit, get_parent())` and uses the returned hit. Then it checks `hit == null or hit.damage <= 0` again, because a later step may resolve a hit down to 0.
- `tests/smoke_checks.gd`: section AAA at the end of `_run()`.

No attack effect, character or scene changed. Melee, projectiles, `Character2D.apply_hit()` and the `take_damage()` shim already ended in `HealthComponent2D.apply_hit()`, so one call there covers all of them.

## Decisions
- **The resolver runs after the guards, not before them.** A hit on a dead or invulnerable target is ignored first and never resolved. Reason: a crit roll (12.3) or a status application (12.4) must not happen for a hit that does nothing. The old guards stay as they were, including `damage <= 0` on the raw hit, so behavior is identical to before.
- **`resolve()` returns the hit, and the caller uses the return value.** 12.1 returns the same object. A later step may return a changed copy (a crit flag, reduced damage). `damaged` carries the resolved hit.
- **The second argument is the health component** (changed in 12.2, which needs `defense` from it; 12.1 first passed the component's parent). It may be null in tests that have no component. `resolve(hit, health: HealthComponent2D)`.

## The checks (section AAA)
| Check | What it proves |
|---|---|
| AAA1, AAA2 | `resolve()` returns the same object with every field unchanged; a null hit stays null. |
| AAA3 | `HealthComponent2D.apply_hit()` resolves once, deals the same damage, and `damaged` carries the very same hit. |
| AAA4, AAA5 | `Character2D.apply_hit()` and the `take_damage()` shim resolve exactly once each. |
| AAA6 | A player melee slash resolves once and deals its definition's damage. |
| AAA7 | A projectile resolves once and deals its damage. |
| AAA8, AAA9 | A hit on an invulnerable or dead target is ignored and never resolved. |

## Not tested yet
That the health component uses the **returned** hit rather than the one passed in. While `resolve()` returns the same object this cannot be observed. 12.2 (defense) is the first step that can test it, and its first check should.
