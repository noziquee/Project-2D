# Phase 12.3 – Critical hits

Written and run in Godot 4.7.2 (headless, Linux): **9 new checks, all passing** (section CCC, CCC1 to CCC9). Expected total after this step: previous total + 9.

## Why
Crits are the second rule in the resolver, and they have to happen before defense so that both steps can be tested in order.

## What changed
- `AttackDefinition2D.gd`: new group **Critical** with `crit_chance` (0 to 1, default 0) and `crit_multiplier` (1 to 10, default 2).
- `HitData.gd`: new fields `crit_chance`, `crit_multiplier`, `is_crit`, and `copy()`. The resolver never changes the hit it is given; it returns a changed copy.
- `AttackEffect2D.gd`: three new **last** arguments of `configure(...)` with defaults (`critical_chance`, `critical_multiplier`, `statuses`), stored on the effect and copied onto every `HitData` it makes. `AttackComponent2D._spawn_effect()` passes the definition's values. Melee and projectile effects needed no change of their own.
- `CombatResolver2D.gd`: rolls the crit and applies the multiplier; `seed_rng(value)` makes rolls repeatable.
- `tests/smoke_checks.gd`: section CCC, and the `fire_arrow` helper now passes the new arguments like the component does.

## Rules
- The crit is rolled **once per hit**, in the resolver, from one seedable `RandomNumberGenerator`. Chance 0 never crits and chance 1 always crits, and neither uses a random number.
- `damage = round(damage x max(crit_multiplier, 1))`, then defense (12.2): `5 x 2 - 3 = 7`.
- The hit that reaches `damaged` has `is_crit = true` and the multiplied damage, so a later step can show a crit number or play a sound from that flag.
- Crit chance comes from the **attack definition**, not from the attacker's stats. A weapon-wide or character-wide bonus can add to it later, in the resolver.
- A hit that is ignored (dead, invulnerable) never rolls, so it does not use up a random number.

## The checks (section CCC)
| Check | What it proves |
|---|---|
| CCC1 | Chance 0 never crits: 100 hits return the same hit with damage 3. |
| CCC2, CCC3 | Chance 1 always crits for damage x multiplier (3 x 2 = 6), the original hit is untouched, and through `apply_hit()` exactly 6 is dealt (applied once). |
| CCC4 | The result is a whole number (4 x 1.5 = 6) and a multiplier below 1 never lowers damage. |
| CCC5 | The same seed gives the same 40 rolls, and chance 0.5 gives a mix. |
| CCC6 | Crit first, then defense (5 x 2 - 3 = 7). |
| CCC7, CCC8 | A melee definition and an arrow definition with `crit_chance = 1` deal double damage. |
| CCC9 | Every shipped attack has `crit_chance = 0`, so nothing in the game crits yet. |

## To use it in the editor
Open an attack `.tres` (for example `PlayerHeavyAttackDefinition.tres`). In the Inspector, open the **Critical** group and set **Crit Chance** and **Crit Multiplier**.
