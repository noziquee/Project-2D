# Phase 9.8a – each attack picks its effect clip (heavy attack uses `heavy_slash`)

Not run (no Godot in the editing environment). Open the project once, read the Output panel, run the smoke test and paste the SUMMARY line and any `CHECK FAIL` lines. This step adds **12 checks** (section PP: PP1a to PP6), so expect your previous total plus 12. Nothing existing changed in the tests.

Expected in the Output log (not failures): an `AttackComponent2D rejected definition` error and a `WeaponController2D` warning naming `no_such_effect_clip` (PP3, PP4), and an `AttackSlash2D requires ... animation 'no_such_effect_clip'` error (PP6).

## Why
`AttackSlash2D` played a clip called `slash` and nothing else, so your `heavy_slash` clip in `AttackSlash2D.tscn` could not be used. This is finding B of the guide (the effect scene contract), the clip-name part only.

## What changed
- `AttackDefinition2D.effect_animation` (new, Effect + Hitbox group, default `slash`): the clip of the effect scene's `AnimationPlayer` this attack plays.
- `AttackSlash2D`: plays and ends with that clip (`effect_animation`), set through a new last argument of `configure(...)` that defaults to `slash`, so existing callers keep working. An empty name means `slash`. New `static scene_lacks_animation(scene, clip)` used by validation.
- `AttackComponent2D`: passes the attack's clip when it spawns the effect; `validate_definition()` refuses an attack whose effect scene lacks the clip, naming it. That covers `set_attack_definition()`, `attacks`, and equipping.
- `WeaponController2D.validate_equip()`: reports the same problem in the dry run.
- `PlayerHeavyAttackDefinition.tres`: `effect_animation = heavy_slash`. Light attacks and the goblin keep `slash`.
- `tests/smoke_checks.gd` (section PP), `docs/phase9/PLAN.md`, README and IMPLEMENTATION_NOTES (one line each).

## What to expect in play
The heavy attack's slash is now your bigger `heavy_slash`: wider scale, and the hitbox sweep reaches 80 px (the light slash reaches 62). The definition's `hitbox_size` is still 28 x 24, so tune it and `hitbox_offset` by eye with **Debug > Visible Collision Shapes**. Damage, knockback and timing are unchanged.

## Using it on another attack
Open the attack's `.tres` and set **Effect Animation** under Effect + Hitbox to a clip that exists in that attack's effect scene. A new effect scene made by inheriting `AttackSlash2D.tscn` can add its own clips.

## Not changed (rest of finding B)
The node paths inside `AttackSlash2D.gd` are still fixed, the effect still spawns at the attacker's origin (no `AttackSpawnPoint`), and it is always a melee sweep (no projectile or area base class).
