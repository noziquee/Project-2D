# Phase 9.4 – combos (built in steps)

## 9.4a – `next_attack` link and validation (done, no behaviour change)

Smoke test: expected `SUMMARY passes=288 failures=23` on Godot 4.7.2 (279 from 9.3 + 9 new checks: W1, W2a, W2b, W3, W4, W5a, W5b, W6, W7).
The 23 failures are the same pre-existing health-value ones listed in `9.2-notes.md`. Not yet confirmed by a run here (no Godot in the editing environment): please run it and paste the SUMMARY line.
No new WARNING lines are expected: section W calls validate_combo_links() directly, and the warnings only print when attacks are registered.

### What changed
- `Characters/Components/Combat/AttackDefinition2D.gd`
  - New **Combo** group with `next_attack: AttackDefinition2D` (empty = no combo). The chaining itself comes in 9.4c.
- `Characters/Components/Combat/AttackComponent2D.gd`
  - `get_all_attacks()`: the default attack plus the extra attacks.
  - `get_next_attack(attack)`: the registered attack a link points to. Returns null for no link, a self link, or a link that is not registered on this component (the link is matched by id).
  - `validate_combo_links()`: returns the problem messages (`Array[String]`), empty when all links are valid.
  - Warnings are printed at `initialize()` and after `set_attacks()`. A bad link never blocks the attack it sits on; it is simply not followed.
- `tests/smoke_checks.gd`: new section W (W1–W7).

### Rules
- A link must be registered on the same `AttackComponent2D` (default attack or an entry of `attacks`), like the AI attack choices in 9.3.
- Self links are invalid. Links back to an earlier attack (A → B → A) are valid.
- Shipped definitions have no link, so nothing changes in game.

### Not changed on purpose
- No window state and no chaining yet (9.4b, 9.4c).
- `combo_window_open` / `combo_window_close` are still accepted and ignored.
- Pre-existing 23 failing health-value checks are not touched in this step; they get their own step so a failure can be traced to the right change.

## 9.4b – combo window state (done, tracked only; no chaining yet)

Smoke test: expected `SUMMARY passes=299 failures=23` on Godot 4.7.2 (288 from 9.4a + 11 new checks, X1–X11), assuming 9.4a passed. Not yet run here; please paste the SUMMARY line.

### What changed
- `Characters/Components/Combat/AttackComponent2D.gd`
  - `combo_window_open` opens the window and `combo_window_close` closes it. Both are honoured only during the weapon clip.
  - The window is closed when the weapon clip ends (recovery starts), when a swing finishes, when it is cancelled or interrupted, and when a new swing starts.
  - New `is_combo_window_open()`: true only while a swing is running, in its weapon clip, with the window open.
  - The window events no longer warn; they are part of `is_known_event` as before.
- `tests/smoke_checks.gd`: section X (X1–X11), using `fresh_far()` so no slash can land on the goblin during the test.

### Not changed on purpose
- Nothing chains yet: a request inside the window still starts a new attack only through the normal gating (9.4c).
- Still no combo clip keys in the scenes, so in game the window never opens (9.4e).
