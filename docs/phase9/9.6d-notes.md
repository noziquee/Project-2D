# Phase 9.6d – player wiring: press, hold and release

Smoke test: expected `SUMMARY passes=361 failures=0` on Godot 4.7.2 (354 from 9.6c + 7 new checks, GG1–GG6), assuming 9.6c passes. The U and BB checks that encoded the old behaviour were rewritten on purpose (listed below). Not run here: please run it and paste the SUMMARY line.

## What changed
- `player.gd` (rewritten; the rest of the file is unchanged)
  - Attack input is sampled once per physics frame (`_sample_attack_input`), before the attack hooks are read.
  - `attack_light` tap (released before `charge_start_time`, 0.1 s): the light attack, sent on release.
  - `attack_light` hold past 0.1 s: begins a charge of `heavy_attack_id`. The release releases the charge, if it is still charging. A THRESHOLD heavy releases by itself; a later release does nothing.
  - A charge that is refused (for example because a swing is running in a combo window) turns the press into a light attack on release, so a press held into the window chains.
  - `attack_heavy` (once a heavy is registered) begins a charge of the heavy directly; its release releases it.
  - With no heavy attack registered, `attack_light` is still the light attack on press.
  - `heavy_hold_time` is renamed `charge_start_time` (0.1 s).
- `Characters/Core/Character2D.gd`
  - New hooks with defaults (controllers that do not charge keep them): `_sample_attack_input`, `_get_charge_begin_requested`, `_get_charge_release_requested`.
  - The physics step samples the input, then releases a charge, then begins one, then starts a light attack request, in that order.

## Checks that changed on purpose
- **U3**: `charge_start_time` is 0.1 s (was `heavy_hold_time` 0.25 s).
- **U9–U11**: a hold past the start time begins a charge (no swing yet); the release starts the heavy swing; nothing else starts after it.
- **U12**: a shorter `charge_start_time` begins the charge sooner (the charge, not the swing).
- **U13**: `attack_heavy` begins a charge; its release, after one more frame, starts the swing.
- **U14–U15**: unchanged in meaning; the dead-player check reads the new hold state (`_light_held`).
- **BB3a**: holding `attack_light` begins the heavy charge, with no swing yet. BB3b, BB4 and BB5 are unchanged in meaning.

## Tests (GG1–GG6)
- Exports; a hold begins a charge; the release starts the heavy swing; a tap under 0.1 s is light; a THRESHOLD heavy releases by itself while held, and releasing afterwards adds nothing; a hold into a combo window chains as the light attack.

## Things to check in play
1. Quick tap: the light attack, on release.
2. Hold: the charge starts after about 0.1 s, the character slows, and the heavy swings on release. The charge clip should show while held (it loops if the clip is set to loop).
3. A THRESHOLD heavy (if you add one) swings by itself while still held.
4. Tap, then tap again in the window: the second is a light chain, as before. Hold into the window: the release chains as light.
5. If the 0.1 s start feels too quick for a light tap, raise `charge_start_time` on the player.

## Known limitation
- The light attack on press without a heavy registered, and the light attack on release with one registered, are two different timings. Both are intended; the second is what makes the tap-versus-charge decision possible.
