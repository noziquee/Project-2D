# Phase 9.6c – heavy charge and release modes (component API)

Smoke test: expected `SUMMARY passes=354 failures=0` on Godot 4.7.2 (343 from 9.6b + 11 new checks, FF1a–FF9), assuming 9.6b passes. Not run here: please run it and paste the SUMMARY line.

Component API and tests only. `player.gd` and the shipped heavy attack are unchanged, so the game still plays as in 9.5a until 9.6d. No scene changes.

## What changed
- `AttackDefinition2D`
  - `enum ReleaseMode { INPUT_RELEASE, THRESHOLD }`.
  - New **Charge** group: `charge_animation` (clip played while charging, may be empty), `release_mode` (default INPUT_RELEASE), `charge_threshold` (seconds, used by THRESHOLD).
- `AttackComponent2D`
  - `begin_charge(id, direction)`: starts a charge. While charging the character is held in the attack state (no other attack or dash), moves at the attack's `movement_multiplier`, and plays `charge_animation`. Starts no swing and emits no `attack_started`.
  - `release_charge(direction)`: turns the charge into its swing (same path as a normal start, so `attack_started`, combo state and the clip all follow). False when nothing is charging.
  - `is_charging()`, `get_charge_time()`.
  - `physics_update` advances the charge clock; a THRESHOLD charge releases itself when `charge_threshold` is reached.
  - `interrupt()` now covers a charge: a charge is interrupted only if its attack is interruptible. `cancel()` clears the charge.
  - `is_aiming_weapon()` also covers a charge, so the weapon points at the aim while charging.
  - `validate_definition()` checks the charge clip exists and that THRESHOLD has a threshold above 0.

## Rules
- A charge is refused while a swing, a dash, hit stun or a cooldown is active.
- Release after a threshold release does nothing. The next `begin_charge` starts a new charge.
- Charge does not change damage or knockback (decision 6 of the plan).
- `try_start_attack` on a charge attack still swings at once. Only `begin_charge` charges. The AI keeps using `try_start_attack`.

## Tests (FF1a–FF9)
- Validation: a valid THRESHOLD attack, a THRESHOLD attack without a threshold, and a missing charge clip.
- An INPUT_RELEASE charge is held for a second with no automatic release, and `release_charge()` starts its swing.
- A THRESHOLD charge releases itself at about 0.5 s with no input, and a release after that does nothing.
- A hit does not cancel a non-interruptible charge; `cancel()` clears it; a charge cannot start during a swing.

## Authoring note
- A `charge_animation` clip that is held for a while should loop in the animation, or it will stop at its last frame on its own.

## Not in this step
- Player wiring (9.6d): press starts a charge, a short tap is still light (the 0.1 s threshold), and the release calls `release_charge()`. `heavy_hold_time` and the old one-shot heavy request change on purpose then.
