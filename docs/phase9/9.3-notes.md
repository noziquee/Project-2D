# Phase 9.3 – the AI chooses between weighted attacks

Smoke test: `SUMMARY passes=279 failures=23` on Godot 4.7.2 (266 after 9.2b + 13 new checks, V1–V13).
The 23 failures are the same health-value ones listed in `9.2-notes.md`.
One expected WARNING in the output (V8/V9) comes from a test that lists an unregistered attack on purpose.

Numbering: this is step 4 of the guide's section 8 ("AI selection"). `9.1-notes.md` called it 9.5; I used the guide's
order (9.3 AI, 9.4 combos, 9.5 heavy attack + goblin lunge in the editor). Rename if you prefer the old numbers.

## What changed
- New `Characters/Controllers/AttackChoice2D.gd` (a Resource): `attack: AttackDefinition2D` and `weight` (default 1, 0 disables).
- `EnemyBehaviorProfile.gd`: new `attack_choices: Array[AttackChoice2D]`. Empty (the shipped goblin profile) = behaviour exactly as before.
- `EnemyAIController2D.gd`
  - With usable entries, the AI picks one by weight, walks until it is inside THAT attack's `ai_attack_range`, requests it by id, then picks again for the next swing.
  - `get_effective_attack_range()` now reads the chosen attack; new `get_chosen_attack()`, `get_chosen_attack_id()` and `reset_attack_choice()`.
  - With no usable entries it reads the character's default attack live (so swapping it still works at once).
  - `rng` (a `RandomNumberGenerator`) can be seeded for tests.
- `tests/smoke_checks.gd`: section V (V1–V13) and a small `attack_choice()` helper.

## Rules worth knowing
- Each entry's attack must also be registered on the enemy's `AttackComponent2D` (its default attack or an entry of `attacks`), because attacks are started by id. An unregistered entry is ignored with one warning.
- Null entries, entries without an attack, and weight 0 are ignored. If nothing usable is left, the default attack is used.
- The pick is kept until the swing is requested. Editing `attack_choices` at runtime needs `reset_attack_choice()` to take effect before then.
- The shared `.tres` profile is one resource for every goblin of that kind. A test (or script) that edits it should `duplicate()` it first.

## Not changed on purpose
- `GoblinBehaviorProfile.tres` and the goblin scene: nothing is chosen between until the goblin has a second attack (9.5).
- The player and `try_start*` APIs.
- Combos (9.4).

## Try it in the editor (after 9.5, or with any second definition)
1. On the goblin's `AttackComponent2D`, add the second `AttackDefinition2D` to **Attacks** (own `id`, own `ai_attack_range`).
2. In the goblin's `EnemyBehaviorProfile`, add two **Attack Choices**: the goblin's default attack and the new one, each with a weight.
