# Phase 9.7b – the sword as a weapon scene

Not run (no Godot in the editing environment). Before the smoke test, open the project once (or run `godot --headless --import --path .`) so Godot registers `Weapons/Sword.tscn` and reads the edited `player.tscn`, and read the Output panel. Then run the smoke test and paste the SUMMARY line and any `CHECK FAIL` lines. This step adds **32 checks** (section JJ: JJ1a to JJ8d) and changes one in place (II1e), so expect your previous total plus 32. The earlier totals were never confirmed in Godot, so compare against what your last run reported.

Game behaviour is meant to be identical: the sword is the same nodes and the same clips, now in their own scene.

## What changed
- **New `Weapons/Sword.tscn`.** Root `MainHand` (Node2D: z_index 1, position (-4, 5), rotation 0.8727, as before), child `weapon` (Sprite2D, `Sword.png`, offset (8, -8)) and `HandAnim` (AnimationPlayer). Its library holds `RESET`, `idle`, `sword_slash_1`, `sword_slash_2`, `sword_slash_return_1`, `sword_slash_return_2`, `sword_heavy_slash` and `sword_charge_heavy_slash`. They were copied out of `player.tscn` as text, unchanged.
- **`player.tscn`.** The inline `MainHand`, `weapon` and `HandAnim` nodes, the eight weapon clips, their library and the `Sword.png` reference are gone. One instance node `WeaponFacingPivot/MainHand` of `Sword.tscn` replaces them, so `WeaponFacingPivot/MainHand/weapon` and `.../HandAnim` still resolve at runtime (tests A1 and A2 are untouched). Nothing else in the file changed.
- **`CharacterContext2D.gd`.**
  - `static find_weapon_player(weapon_root)`: the child called `HandAnim` or `WeaponAnimation`, otherwise the first `AnimationPlayer` child, otherwise null.
  - On the player rig the weapon is `WeaponFacingPivot/MainHand`; if that does not exist, any other `Node2D` child of `WeaponFacingPivot` that has a weapon player.
  - `bind_weapon(weapon_root)`: points the context at a weapon mounted later; refuses (warning, old weapon kept) when it has no player. It does not reconnect `AttackComponent2D`'s `animation_finished` signal; that belongs to equipping in 9.7c.
  - The goblin layout (`AnimatedSprite2D/Weapon/WeaponAnimation`) is found the same way as before. One loosening: a goblin weapon whose player has another name is now found by type instead of disabling attacks.
- **`WeaponDefinition2D.gd`.** `instantiate_weapon()` (a new Node2D or null) and `validate_scene()` (the scene instantiates, its root is a Node2D, it has a player, every clip the attacks name exists; empty when there is no scene). `validate()` is unchanged.
- **`SwordWeaponDefinition.tres`.** `weapon_scene` = `Weapons/Sword.tscn`.
- **`tests/smoke_checks.gd`.** Section JJ (below) at the end, and **II1e changed on purpose**: it expected no weapon scene (9.7a) and now expects `Weapons/Sword.tscn`.
- `docs/phase9/PLAN.md`.

## Tests (section JJ, 32 checks)
JJ1a-f the scene loads, root, sprite, player, pose and the eight clips; JJ2a-d `find_weapon_player` (by name, by type, none, name wins over order); JJ3a-c every method track of the clips resolves to the character when mounted under `WeaponFacingPivot`, every key is a known `attack_event`, every sword attack's clip spawns an effect; JJ4a-d the context finds a weapon mounted as `Blade`, `bind_weapon` accepts and refuses, `MainHand` is preferred; JJ5a-f the shipped player mounts the scene, its context reads the weapon from it, `player.tscn` stores only the instance, attack ids and z_index unchanged, the sword's scene validates, `instantiate_weapon()`; JJ6a-c a real swing spawns its effect and finishes; JJ7a-b the goblin layout still binds and keeps `slash` and `lunge`; JJ8a-d `validate_scene` and `instantiate_weapon` on weapons built in code (no scene, root not a Node2D, no player, missing clip).

One `push_warning` ("weapon 'Bare' has no AnimationPlayer; keeping the current weapon") is expected in the log for JJ4c.

## Editing the sword in the editor
- Open `Weapons/Sword.tscn` to edit the sprite or the clips. Its `attack_event` tracks use the path `../..`, which only resolves when the sword is mounted under `WeaponFacingPivot` on a character, so the Animation panel may show those tracks as invalid when the sword is opened on its own. That is expected; the keys are still there.
- In `player.tscn` the sword now shows as an instance. Using "Editable Children" on it would save overrides into `player.tscn`; prefer editing `Sword.tscn`.
- The clips are shared by every instance of the scene (one library resource). The smoke test already adds and removes aliases on it and cleans up after itself.

## Risks, and what to look at first
- **Hand-edited scene (the same risk as 9.4e/9.5a/9.5b).** `Sword.tscn` was written as text and `player.tscn` was edited as text. Godot may add a `uid` to `Sword.tscn` and rewrite headers the first time you open and save. If the Output panel shows a load error for either scene, send it before running the smoke test.
- **Look in play:** the sword is drawn in the same place, swings with the same arc, and aims at the mouse as before (`WeaponFacingPivot` is still on the player).
- Method-track warnings from `CharacterContext2D` at start-up (a path that does not resolve) would mean the mount point is wrong; none are expected.

## Seen while reading, not changed
- `DefaultAttackDefinition.tres` (the player's light attack) still has Release Mode = Threshold and Charge Threshold = 2.0 (see 9.7a); it does nothing while the light attack is never charged.
- The weapon library keeps an `idle` clip that nothing plays. It moved with the rest; remove it later if you do not want it.
- Still open for 9.7c: equipping must reconnect the attack component to the new weapon player's `animation_finished` signal and free or reuse the old weapon node. `bind_weapon()` only updates the context.
