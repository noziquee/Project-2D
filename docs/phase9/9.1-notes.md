# Phase 9.1 – `attacks` array and `try_start_attack(id)`

Smoke test: `SUMMARY passes=264 failures=0` on Godot 4.7.2 (244 from 9.0 + 20 new checks, S1–S20).
The expected ERROR/WARNING lines in the output come from the tests that feed bad data on purpose.

## What changed
`Characters/Components/Combat/AttackComponent2D.gd`
- New export `attacks: Array[AttackDefinition2D]` – extra attacks, selectable by id. `attack_definition` stays the default attack and is also selectable by its own id, so list only the additional ones.
- New `try_start_attack(attack_id, direction)`. Empty id = "no attack" (returns false). Unknown id = false + a warning listing the known ids. Same gating as before.
- `try_start(requested, direction)` is unchanged for callers; it now starts `definition` through the same internal path.
- Helpers: `get_attack(id)`, `has_attack(id)`, `get_attack_ids()`, `get_active_attack_id()`, `set_attacks(list)` (returns how many were accepted).
- Bad entries (null, empty id, same id as the default, duplicate id, missing clip) are skipped with a message that names the problem. They never disable the default attack or the other extras.
- One cooldown is shared by all attacks; it is the `cooldown_duration` of the attack that just finished.

`tests/smoke_checks.gd` – new section S (S1–S20).

## Not changed on purpose
- Input and `Character2D._get_attack_requested()` still return a bool (9.2).
- The AI still reads its swing range from the default `definition` (9.5).
- No scene or .tres edits; nothing in the editor changes until you add entries to `attacks`.

## Try it in the editor
Select the `AttackComponent2D` node, expand **Attacks**, add an `AttackDefinition2D` with its own `id`, and call `attack_component.try_start_attack(&"your_id", direction)`.
