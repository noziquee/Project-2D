# Phase 9.2 – attack ids and input (built in steps)

## 9.2a – `_get_attack_requested()` returns an attack id (done)

Smoke test: `SUMMARY passes=251 failures=23` on Godot 4.7.2.
Before this step the same tree gave `passes=241 failures=23` (264 checks), and the failing checks are identical.
The 10 extra passes are the new section T (T1–T10).

### The 23 existing failures are not from this phase
They come from the health values you retuned in the editor: the player's `HealthComponent2D.max_health`
is 100 (was 5) and the goblin's is 20 (was 3). Checks B3, F3–F5, K1, K3–K6, K8, K12–K14, L4, L5, L8 and
R8, R11, R13, R14, R16, R17, R19 still assume the old numbers. They need to read the values from the scene,
like K2/K20/Q2 already do. Not touched here.

### What changed
- `Characters/Core/Character2D.gd`
  - `_get_attack_requested()` now returns `StringName` (empty = no attack) instead of `bool`.
  - The call site uses `attack_component.try_start_attack(id, direction)` instead of `try_start(bool, direction)`. Gating is unchanged.
  - New `get_default_attack_id()` returns the attack component's default attack id (empty if none).
- `Characters/Controllers/EnemyAIController2D.gd`
  - `_attack_requested: bool` became `_requested_attack_id: StringName`.
  - `consume_attack_request()` returns that id and clears it. It is the character's default attack id until the AI can choose (9.3).
- `Characters/Enemies/BasicEnemy2D.gd`: return type follows the controller.
- `player.gd`: still reads the existing `attack` action; it now returns the default attack id on press.
- `tests/smoke_checks.gd`: new section T (T1–T10): default id, empty id with no input, press starts the attack by id, id follows a swapped default definition, dead player requests nothing, goblin AI starts its attack by id and the request is consumed.

### Not changed on purpose
- `AttackComponent2D.try_start(bool, ...)` stays (the older tests and any caller that only wants the default attack use it).
- No input map changes yet: `attack_light` / `attack_heavy` are 9.2b.
- Behaviour in game is unchanged.

## 9.2b – `attack_light` / `attack_heavy` input (done)

Smoke test: `SUMMARY passes=266 failures=23` on Godot 4.7.2 (251 after 9.2a + 15 new checks, U1–U15).
The 23 failures are the same health-value ones listed above.

### What changed
- `project.godot`
  - The `attack` action is renamed `attack_light` (still left mouse button). If you edit the Input Map in the editor, check that nothing of yours still reads `attack`.
  - New `attack_heavy` action with **no default binding**. Add a key or gamepad button in Project Settings > Input Map if you want a direct heavy button.
- `player.gd` (new exports, all with defaults, no scene edit needed)
  - `light_attack_id` (empty = the component's default attack, `player_light`), `heavy_attack_id` (`player_heavy`) and `heavy_hold_time` (0.25 s).
  - `attack_light` held for `heavy_hold_time` sends the heavy id **while the button is still down**, once per hold. A shorter press sends the light id when the button is **released**.
  - `attack_heavy` sends the heavy id immediately.
  - If the character has no attack with `heavy_attack_id` (true until 9.5), `attack_light` sends the light id **on press** like before, and `attack_heavy` is ignored without a warning.
- `tests/smoke_checks.gd`: T checks use `attack_light`; new section U (U1–U15): the two actions, export defaults, behaviour with and without a registered heavy attack, tap, hold, one heavy per hold, `heavy_hold_time`, direct heavy, `light_attack_id`, dead player.
- `IMPLEMENTATION_NOTES.md`: controls list updated.

### Behaviour to know about
- Once a heavy attack exists, a tap starts on release, so it is up to `heavy_hold_time` later than a press-to-fire attack. Lower `heavy_hold_time` if it feels laggy.
- Nothing is requested while the player is dashing (the base class does not ask), so a tap or hold that spans a dash resolves after the dash.
- The enemy is unchanged (it still sends its default attack id; selection is 9.3).

## 9.2c – left

## Superseded
`heavy_hold_time` (0.25 s) became `charge_start_time` (0.1 s) in 9.6d. The heavy attack id is no longer a fixed export: since 9.7d-1 it comes from the equipped weapon (`player.gd` `get_heavy_attack_id()`), and `light_attack_id` / `heavy_attack_id` are empty overrides. The 23 health-value failures noted here were repaired in 9.0b.
