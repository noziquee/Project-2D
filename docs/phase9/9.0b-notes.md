# Phase 9.0b – health-value checks repaired (test-only)

Smoke test: expected `SUMMARY passes=318 failures=0` on Godot 4.7.2. That is the same 318 checks as after 9.4e, with the 23 health-value failures repaired. Not run here (no Godot in the editing environment): please run it and paste the SUMMARY line. If any failure remains, paste its CHECK FAIL line; it would be a check I did not identify from the 9.2 notes.

No game code changed. Only `tests/smoke_checks.gd` changed. No checks were added or removed.

## What was wrong
The 23 failures came from two shipped values that changed after the tests were written:
- the player's health (now 100, the tests assumed 5) and the goblin's (now 20, they assumed 3);
- the player's light attack damage (now 5, the tests assumed 1 per hit).

## How each group was fixed
- **Damage per hit (B3, L4, L5, L8).** Now compare against the attack's own `damage` (`p.attack_definition.damage`), not a fixed 1.
- **Death and arithmetic (F3–F5, K1, K3–K6, K8, K11–K14).** These need a small health pool to test logic. A new helper `set_player_health(player, hp)` sets max and current health together, and F, K1–K10 and K11–K14 use it with 5 hp. Like `set_detection_radius`, it keeps the test about the logic, not the shipped tuning.
- **Health bar (R8, R11, R13, R14, R16, R17, R19).** The bar thresholds (60 %, 40 %, 20 %) are now fractions of the real max (`r_max`), so the bar checks hold for any tuning. R17 was in the list and is covered by the same change.

## Not changed on purpose
- The shipped values (player 100 hp, goblin 20 hp, damage 5) are untouched.
- No checks were loosened: every assertion still checks the same behaviour.
