## Light combo (what you asked for, and how it is built)
- `Attack 1 -> Attack 2` chains when a press lands inside a combo window (the `combo_window_open` / `combo_window_close` keys in the clip). Nothing chains by itself.
- A press inside **Attack 2's** window starts **Attack 1** again (a new combo). Implemented as one rule in `AttackComponent2D`: at the end of a chain (the attack has no `next_attack`), a window press starts the combo's first attack. No resource points back at another, so there are no circular `.tres` references. The first attack is remembered at runtime (`_combo_root`), never in a resource.
  - An attack that was started on its own with no link is its own first attack, so it still repeats itself, as before.
  - A deliberate self link (`next_attack` = the attack itself) still means "repeat this attack".
- Window closes with no press: the return clip of the attack performed last plays (`sword_slash_return_1` after attack 1, `sword_slash_return_2` after attack 2). This was already in place (9.6b) and is now tested with the real clips.
- During the return nothing can start. A press (or tap) is refused and not remembered, so the return always finishes first. The cooldown (0.05 s) then runs, and the next press is Attack 1.
- Flows covered: `1 -> 2 -> return_2 -> 1 -> 2 -> return_2`, `1 -> 2 -> 1 -> 2 ...` (new combo inside attack 2's window) and `1 -> return_1`.

## Heavy attack
- The per-attack charge fields already existed (9.6c) and are unchanged: `charge_animation`, `release_mode` (`INPUT_RELEASE` or `THRESHOLD`) and `charge_threshold`. Each heavy attack sets its own.
  - `INPUT_RELEASE`: charges until the input is released (a bow's mouse-up). Nothing releases it earlier.
  - `THRESHOLD`: releases by itself after `charge_threshold` seconds, while the button is still held. Releasing the button afterwards does nothing, and the held button does not start a second charge. The next press starts a new one.
- New: `AttackComponent2D.get_charge_ratio()` (0 to 1) for a charge bar. It fills over `charge_threshold`. For an `INPUT_RELEASE` attack it is 0 unless a threshold is set, and then it only scales the bar.
- Changed in `player.gd`: a held button now keeps asking for the heavy charge until it begins. Before, one refused request was never retried, so holding through a swing or a return never charged. Releasing before the charge begins is still a light tap, so a tap or hold inside a combo window still chains.
- The shipped `player_heavy` is `INPUT_RELEASE`. To make a charged slash that auto-releases after 2 seconds, open `PlayerHeavyAttackDefinition.tres`, set **Release Mode** = Threshold and **Charge Threshold** = 2.0. No script edit.
